# NISAR L-band / Sentinel-1 C-band training notebooks

A hands-on, notebook-based progression from a NISAR L2 product to dual-pol polarimetry, run on real
data over the Vosges (France) clear-cut site of this feasibility study. Nineteen notebooks, each
ending with a checkpoint that must print `Module NN STATUS: PASS`.

The structure follows the open **NISAR GCOV training toolkit** of D. K. Pandey
([`dharmendraisro/nisar-polarimetric-training`](https://github.com/dharmendraisro/nisar-polarimetric-training),
Apache-2.0), rewritten for what is actually acquired over Europe:

| | Original toolkit | This series |
|---|---|---|
| NISAR mode | L-band quad-pol, S-band compact-pol | **L-band dual-pol HH/HV** (`DHDH`), the mode acquired over Europe |
| Polarimetric matrix | 3x3 C3/T3 from GCOV | **2x2 C2 rebuilt from the complex GSLC** (the dual-pol GCOV stores no cross term) |
| Decompositions | Cloude–Pottier, Pauli, Freeman–Durden, Yamaguchi, m-χ | **dual-pol H/A/α** (Cloude 2007), **DpRVI** (Mandal et al. 2020), RVI, Stokes |
| Second sensor | NISAR S-band | **Sentinel-1 C-band VV/VH**, same C2 methods (SNAP graph `s1_c2`) |
| Application | generic | **clear-cut detection**, L-band vs C-band |

No code is copied from the original toolkit. All processing lives in the `nisar_s1` package
(`product`, `polarimetry`, `maps`, …) so it can be reused outside the notebooks, and — since ESA's
**ROSE-L** L-band mission is expected to deliver L2 products with a similar geocoded layout — on
ROSE-L data later. NISAR L2 products are generated by JPL with the open-source **ISCE3** framework.

## Modules

| # | Notebook | Content |
|---|---|---|
| 01 | Setup and product selection | ASF search over the AOI, local or streamed product, footprint maps, session file |
| 02 | Session check and product orientation | frequencies A/B, polarizations and terms discovered from the file, name/content cross-check |
| 03 | Metadata-first explorer | HDF5 tree, identification, chunking, units, processing metadata, own GIS layer |
| 04 | GCOV covariance explorer | diagonal vs off-diagonal terms, γ⁰ vs σ⁰ (RTC factor), number of looks |
| 05 | Large data and windowed access | memory guard, chunk-aligned vs strided reads, tile-wise processing, remote streaming |
| 06 | Spatial subsetting | lon/lat AOI → projected window, validation rules, AOI handed to the session |
| 07 | QC, statistics and masks | `mask` layer, no-data, outliers, statistics per land unit (cut / control forest) |
| 08 | Visualization | dB display, robust stretch, dual-pol RGB (HH, HV, HH/HV) |
| 09 | Frequencies and batch processing | 20 MHz vs 5 MHz grids, all terms x all frequencies to GeoTIFF |
| 10 | GeoTIFF export and QGIS validation | read-back checks (CRS, pixel, values), overlay with independent polygons, QGIS checklist |
| 11 | GCOV capstone | 11-date time series: the summer clear-cut in L-band HH and HV |
| 12 | Troubleshooting | environment report, typical errors and fixes, session reset, memory |
| 13 | Polarimetric mode discovery | what NISAR acquires here, which methods carry over (decision table) |
| 14 | C2 reconstruction and validation | multilooked C2 from GSLC, physical checks, comparison with GCOV of the same date |
| 15 | Observables and eigen-analysis | span, ratio, co/cross correlation, eigenvalues, tile-wise processing |
| 16 | Dual-pol H/A/α | maps and H–α plane before / after the cut |
| 17 | Dual-pol vegetation indices | DpRVI, RVI, Stokes parameters; why Pauli/Freeman–Durden/Yamaguchi do not apply |
| 18 | Sentinel-1 C-band counterpart | SNAP C2 (VV/VH), same decompositions |
| 19 | Polarimetric capstone | change of each parameter on the cut vs control, AUC, L-band vs C-band |

## Data

Nothing is stored in the repository. `notebooks/kit_config.yaml` defines the granules and the AOI;
data go to `data_dir` (default `<data_root of config/params.yaml>/kit`).

* **01–12** use one NISAR GCOV (2 GB). The notebooks open the local copy if present, otherwise they
  stream the file from ASF over HTTPS (only the chunks that are read are transferred).
* **13–19** use AOI subsets of two NISAR GSLC (13 GB each, only a 6 km window is streamed) and the
  Sentinel-1 C2 matrices. Prepare them once with
  `python scripts/kit/k1_prepare_data.py` (needs ESA SNAP for the Sentinel-1 part).
* **11** and **14** also read the NISAR GCOV GeoTIFFs of the feasibility study
  (`scripts/04_fetch_nisar.py`).

Earthdata credentials: `~/.netrc` (machine `urs.earthdata.nasa.gov`), read by `earthaccess`; never
written in a notebook or in the configuration.

## Running

```bash
conda activate nisar_s1
jupyter lab notebooks/            # interactive, in order 01 → 19
# or headless, with outputs saved in the notebooks:
python scripts/kit/k3_run_notebooks.py 1 19
```

The notebooks are regenerated from `scripts/kit/k2_build_notebooks.py` (single source of the cells).
